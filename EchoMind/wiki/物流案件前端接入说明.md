# EchoMind 物流案件前端接入

前端已接入 Python 后端，可通过 http://localhost:5174 使用。当前只启动 Python 服务链路，Java 后端不在本次部署范围。

## 使用步骤

1. 打开页面，选择 Python。
2. 新对话页点击“体验物流异常案件 · 使用演示身份 demo-user”。这会明确切换到模拟订单所属身份并填入 DEMO1001 问题，用户点击发送后提交。
3. 页面显示疑似丢件案件、订单号、运单号、当前状态和下一步；待确认时可点击“确认创建模拟工单”。
4. 建单完成显示 MOCK 工单号并隐藏确认按钮。刷新页面从后端恢复当前案件，不靠解析聊天文本判断状态。
5. 破损示例可发送“包裹破损，订单号 DEMO1003”，登记材料声明后再确认，或转人工核查。

## 接口

POST /chat 新增可选 logistics_case 字段。GET /logistics/case?user_id=...&conv_id=... 返回当前会话案件快照或 null。快照仅包含案件 ID、类型、状态、订单/运单、模拟工单号、下一步、材料声明和 can_confirm，不返回完整内部事件或用户身份。
生产 Token 用户仅能查询自己的 user_id；SQLite 查询还校验 conv_id，错误会话指针不能读取其他会话的案件。
转人工时把未完成案件状态持久化为 manual_review，刷新后不重新出现可用确认按钮；手工发送确认也不会直接创建工单。

## 前端行为

案件卡片跟随消息区域滚动，避免小屏幕上挤掉聊天内容。只有后端返回 awaiting_confirmation 且 can_confirm=true 才显示确认按钮；请求进行时禁用案件操作。切换后端、新对话或修改身份时清除当前卡片，过期恢复请求不能覆盖新会话。材料按钮只登记用户已提交材料的声明，不执行文件上传或图片审核。
刷新恢复的是案件快照；页面没有新增历史聊天消息列表恢复功能。后端仍使用原有持久化对话作为下一轮上下文。

## 本机部署

在 EchoMindFrontend 中运行 npm ci 和 npm run build。随后在 EchoMind 后端目录运行：

```powershell
docker compose -f docker-compose.yml -f docker-compose.local-check.yml -f docker-compose.frontend-local.yml up -d --no-build --pull never
```

前端 dist 通过只读挂载交给 Nginx，5174 端口仅绑定本机；/api/python 路径代理到现有后端。修改前端后重新 npm run build 并刷新页面。
