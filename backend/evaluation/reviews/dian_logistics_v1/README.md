# 物流测试样本的模型辅助初审

原始测试文件仍为 20 案、28 轮，内容与期望不改动。[初审表](codex-initial-review.csv)逐轮记录原期望、演示政策依据和语义要求。填写者为 Codex，独立人工复核数为 0；该表没有填写或覆盖双人复核者、裁决者字段。

25 轮的程序期望在演示约束下合理；DIAN-012 的 1 轮和 DIAN-016 的 2 轮保留目标歧义，共 3 轮不确定。前者可能只是询问错发材料，后者可能只是询问核查步骤，不能凭问法强制认定用户申请了案件处理。DIAN-016 的确认轮取决于首轮是否建立了待确认案件。

本次先记录初审与[执行协议](protocol.json)，再运行固定版本。原 runner 对全部 20 案依原期望评分，不移除歧义项，也不拿输出倒改期望。报告另列这两案，不把原始流程通过率当作可信业务准确率。

原始 split 历史上已被构造者和代码测试读取，不能称为独立新盲测。此次只跑一轮候选，不调生产路由、提示词或规则；若之后依据失败修复，已曝光案件应归入回归，新的泛化验证另用未调参样本。真实双人复核仍按原[复核说明](../../../wiki/DiAn测试集人工复核说明.md)独立执行。

固定候选回放已完成，见[首轮评测](../../../wiki/DiAn-物流20案固定版本首轮评测.md)与[实际回复逐轮复核](codex-observed-review.csv)。原始流程 14/20 案通过，DIAN-033 后两轮因首轮失败未执行。DIAN-010 的“怎么办”目标歧义在回放后追加，原初审未识别它；两个表分别保存，未倒改原判断。模型辅助语义结论与原 runner 的 `pending_human_review` 状态分别保留，独立人工复核仍未完成。

后续已完成[类别边界优化](../../../wiki/DiAn-错发与签收争议语义边界优化验收.md)：先冻结 [12 条开发配对协议](intent-boundary-protocol.json)，再执行 5 轮新旧识别器对照与一次实际 API 回归。新增[候选实际回复复核](codex-boundary-observed-review.csv)，原先各表与原测试文件继续保留。类型改善、目标退化、代价和政策依据问题分别记录，不合并成一个“最终业务准确率”。

后续咨询实验见[偏差复盘](../../../wiki/DiAn-咨询开发诊断与实验偏差复盘.md)。目标约定v2的标签与旧标签分开保存，35/40到40/40不能称为泛化准确率提升；两次回复提示词候选未通过语义复核，均已撤回。[40轮开发复核](consultation-development-review.csv)保留失败，现有样本不再用于追分。
