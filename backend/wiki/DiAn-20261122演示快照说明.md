## 复现顺序

先按根目录README安装依赖。以下命令从`backend`运行，复用本机既有配置；不复制覆盖现有`.env`。

1. **完整审核与权限边界，模型使用测试替身、实际API和数据库执行：**

```powershell
python -m pytest -q tests/test_chat_reliability.py -k damage_chat_reaches_ticket
```

2. **独立HTTP工单丢响应、进程退出后的核对恢复：**

```powershell
python -m pytest -q tests/test_logistics_http_operation.py -k "response_lost_reconciles_without_duplicate or process_crash_after_remote_commit_recovers"
```

这些是受控工程演示，不将测试替身算作真实模型质量。若面试现场需要对话展示，默认使用`demo-user`、`DEMO1003`，依次申报破损、声明外包装/面单/商品问题照片已提交、独立确认、再次提交，说明实际工单仍为模拟。

3. **有可用凭据及本地授权绑定时，真实只读查询：**

```powershell
python -m evaluation.verify_kdniao_chat --order-id LIVE1002 --output data/kdniao/interview-live-check.json
```

此命令会尝试一次真实供应商查询，可能消耗额度；重复请求场景使用同一回执，不再出站。LIVE1002只是本机别名，公开仓库不附带运单、验证信息或密钥。已有验收可直接展示[脱敏汇总](../evaluation/kdniao_live_8002_acceptance_20261122.json)，不为展示反复消耗查询。

历史样本回放不访问承运商，但仍需可用的模型配置：

```powershell
python -m evaluation.verify_kdniao_chat --response-fixture evaluation/fixtures/kdniao_signed_redacted.json --output data/kdniao/interview-response-replay.json
```

这是用户提供历史响应的回放，不冒充实时供应商查询。

## 冻结边界

- 真实只读验收本次仅1个授权运单；源查询和完整回复留在本机，公开只保存脱敏证据。模型服务未锁定供应商内部快照。
- 本次未启动前端做浏览器验收，也未将真实物流写入责任判定或工单执行。Temporal保持可选，不作为本轮新增工作。
- 历史50案中强制物流工具路径的断言与新破损契约存在差异，不能把历史通过率用于当前版本整体效果。自然语言独立人工复核仍为0。
- 冻结后停止围绕当前曝光题调提示词；必要修复另作提交，保留这个快照供比较。进一步生产化需真实订单身份、写接口契约和业务审核制度。
