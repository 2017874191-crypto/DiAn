# DiAn A2 物流上下文消融验收

承接[工程能力审查 A2](DiAn-AgentInfra工程能力审查与优化方案.md)和[A1 意图消融](DiAn-A1意图消融复验.md)。物流异常状态机根据本轮信息、主体所属的持久案件、模拟订单与轨迹、业务策略和确认状态执行。最近消息继续供意图识别使用。会话摘要、用户画像和情景召回原先在每次聊天路由前读取，但物流状态机没有使用这些生成背景。

## 对照

从开发集选择 10 案、17 轮，覆盖破损举证、签收争议、缺单号补全、非所属订单、订单与运单冲突、询问及否定确认、人工核查、查件和运费。五轮重复相同数据。基线四组交错顺序，每组使用完整背景、去掉画像、去掉情景召回、或仅保留最近消息及结构化状态。候选版本保留相同数据，只在实际执行生成回复的 Agent 前装载背景。

固定实际 ASGI `/chat` 路由、SDK 本地模型传输替身、Redis 协议替身、独立 SQLite、物流向量关闭。背景中预置一笔与丢件请求冲突的旧订单，情景记忆和画像替身每次读取各等待 20 毫秒。每轮有一个建单案例在确认前删掉 Redis 最近消息和结构化状态，保留 SQLite 案件。回放检查持久案件状态、同案连续性、核验顺序、授权和工单数量。

## 实现与边界

- `/chat` 先读最近消息和结构化状态，随后用 SQLite 当前案件恢复业务指针。固定物流、人工升级和固定澄清可直接返回或进入状态机。普通问答和需要模型生成的物流回退会补齐摘要、画像及情景历史。
- 支持 Agent 并行前装载一次，该轮共享同一份背景。装载后复核会话租约，已经被接管的请求不能调用回答模型或写入新回执。响应性能记录以 `memory_background` 标记实际读取。
- 改动限于聊天前台读取。画像更新、摘要压缩、启动依赖、Temporal、意图模式默认值及业务确认规则沿用现有配置。实验没有测量生产请求延迟、真实 Chroma 故障或通用问答的人工语义质量。固定模型报告的 token 仅为替身数据，未用于成本结论。

## 复现

在基线和候选提交的 `backend` 目录分别安装同一套依赖。基线使用 `eager`，候选使用 `routed` 并执行回归测试。

```powershell
New-Item -ItemType Directory -Path data -Force | Out-Null
python -m evaluation.compare_logistics_memory --phase eager --output data/memory-ablation-eager.json
python -m evaluation.compare_logistics_memory --phase routed --output data/memory-ablation-routed.json
python -m pytest -q tests/test_chat_reliability.py
```

候选版本的 Windows 本机后端全量回归通过 283 项测试，含物流固定流程、生成回复回退、多 Agent 共享背景和租约接管的回归。全量命令为 `python -m pytest -q tests`。
