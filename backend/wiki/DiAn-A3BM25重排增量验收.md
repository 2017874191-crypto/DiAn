# A3 BM25 重排增量验收

本轮在代码 `14902e1` 上固定每题 BM25 二十个候选，对照直接前三与现有模型重排。30 个开发问题中，前三命中从 19 题提高至 29 题，nDCG@3 从 0.3556 提高至 0.7022，代价为每题一次模型调用和当轮约 2.28 秒的额外重排 P95。保留 BM25 加重排作为后续验证候选，业务语料与独立样本的效果仍需评估。

## 设计

输入来自[候选对照记录](../evaluation/rag_candidate_bm25.json)，语料沿用固定 299 段和 30 题。每题两组的完整候选对象 SHA-256 相同，直接组三条 ID 和相关性指标与上轮原样一致。模型仅接收问题、候选正文与检索元数据。qrels 由本地计算指标使用。

通过现有 `MCPToolManager` 和 `compare_rerank_contract.run_case` 执行重排，沿用 200 字符候选展示、输出解析和回退。温度为 0，输出上限 2048 token，最多一次逻辑调用，SDK 重试为 0。评测共享直连客户端，两组逐题交替先后执行。

本轮仅改变排序机制。候选从记录中加载，耗时单独测量排序过程，排除 BM25 索引与查询、候选对象构造和整个聊天链路。表中直接组的亚毫秒耗时只包含截取、哈希与指标计算等本地操作。

共 30 次模型调用，错误为 0，30 次均返回完整有效索引，无兼容补齐。供应商报告输入 73,799 token，输出 1,534 token，缓存读取和缓存创建均为 0，全部调用均有用量字段。实际费用依账户计费确定。

按题比较，新增整题命中 10 题，原有命中丢失 0 题。nDCG@3 为 22 胜、6 平、2 负。两道退步题均保留整题命中，但排序质量下降。

- `3359372#0` 古罗马文化遗产问题。原前三全为已标注正例，重排第三条变为已标注负例，nDCG 从 1.0000 降至 0.7654。
- `362110#0` 北洋水师创始人问题。两组前三均有两个已标注正例，重排将负例放在第二位，nDCG 从 0.7654 降至 0.7039。

唯一整题未命中的 `3425282#0` 日环食问题，已知正例在 BM25 候选阶段被漏掉，与[候选召回验收](DiAn-A3候选召回BM25对照.md)的观察一致。

## 取舍与边界

这次同候选对照观察到了模型重排的增量。额外调用换来了十道整题命中和更高的平均相关性，仍有两道排序退步，且约两秒的排序等待需要结合产品时延目标判断。直接 BM25 保留为零模型调用的效果基线。

全部问题都已经在开发实验中曝光，后加入 22 题只是相对早期八题的分组。只有一轮真实模型观测。语料由上游标注段落并集构成，未标注段落按零增益计分。200 字符候选展示和公开标注的语义疑点继续限制结论。29/30 表示至少一个已标注正例进入前三，最终答案正确性需要独立验收。

后续优先在业务检索草稿完成真实人工复核后，用固定版本比较直接 BM25 与 BM25 加重排，报告引用正确性、回答语义、超时回退和实际耗时。若先评估更多公开样本，应在运行前固定数据划分、质量收益目标与可接受的额外时延。模型重排作为候选能力进入后续评估。

## 复现与核对

在 backend 目录准备好固定语料和本地模型配置后运行。

```powershell
python -m evaluation.compare_bm25_rerank --output data/rag-a3/bm25-rerank.json
```

[逐题结果](../evaluation/rag_bm25_rerank.json)保存完整候选 ID、候选哈希、模型回复、调用用量、事件、排序耗时和指标。程序使用当前模型配置，回复正文只针对本批公开语料保存。

运行后核对了 30 对候选哈希相同、直接结果与上轮逐条一致、重排输出 ID 属于候选、每题仅一次实际模型调用、全部用量可用以及汇总与逐题重算一致。本轮交付包含评测入口与实测记录。
