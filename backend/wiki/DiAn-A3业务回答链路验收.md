# A3 业务回答链路验收

本轮在现有 GeneralAgent 回答入口上回放 30 个业务问题，发现检索覆盖充分的语料仍会被跳过，回复会补充没有依据的时效、操作细节或服务承诺。已调整 GeneralAgent 提示词，明确项目问题先参考知识库、保留适用条件，并按实际工具范围描述能提供的服务。

修复后的同题复跑中，知识库工具调用覆盖从 15/30 提高至 25/30，关键的退款时效、物流更新、积分换算和加急配送规则得到纠正。仍发现一条状态含义解释有误，保留在案例记录。

## 覆盖范围

回放使用实际 `GeneralAgent.handle()`、模型工具选择循环和 `build_shared_rag_tools` 共享工具桥接。模型自行选择是否检索，未强制 tool_choice 或预先塞入答案。检索由评测专用 BM25 适配器实现，尊重模型选择的查询和 top_k，返回原九段演示语料。候选正文完整返回，沿用正常 Agent 的回答系统提示与生成参数。

这是单 GeneralAgent 的回答过程验证。HTTP /chat 路由、意图识别、其他角色、回复合成、Skills、会话恢复和真实物流接口需要各自的链路验收。生产知识库仍有既有向量、改写流程，本轮 BM25 接入位于评测适配器。

没有将复核标签或必要事实放入模型输入。标签来源为 Codex 模型辅助初审，判定观察也由同一助手检查，独立人工评审数量为 0。不会据此汇总独立语义通过率。

## 复现的偏差与修改

| 问题 | 基线观察 | 最终候选观察 |
|---|---|---|
| 003，已发货退款 | 未检索，给出拒收流程及 3–7 工作日到账 | 引用先完成退货，保留审核 1–3、到账 5–7 工作日 |
| 006，物流更新 | 未检索，给出 24–48 小时 | 引用通常发货后 24 小时内更新 |
| 013，积分换算 | 未检索，反问积分种类 | 引用 100 积分抵扣 1 元 |
| 016，加急配送 | 未检索，反问地址、商品和期望时间 | 引用 1–2 工作日、15 元 |
| 018，已发货改地址 | 推断可申请拦截，并表示能核验物流 | 说明资料只规定发货前，发货后需核验 |
| 023，签收争议核查 | 扩充语料未列出的核查与材料 | 引用签收争议核查，说明清单和时效尚无依据 |
| 027，已提供材料 | 澄清场景，同时承诺协助转人工 | 澄清案件类型，引导用户自行联系专业客服 |
| 028–030，金额与实时状态 | 部分回复索取无工具支持的身份字段或承诺转接 | 明确资料或查询能力缺失，引导用户自行核实 |

修改集中于 GeneralAgent 的 system prompt。已提供知识库工具时，项目退款、配送、积分、账户安全和技术排障问题先检索。规则不完整时保留未知项，避免将发货前条件推到发货后。已确认本轮工具范围不具备真实订单、退款执行或人工转接，回复应建议用户自行使用对应渠道。

模型仍会针对密码安全常识直接回答，针对缺少案件类型的问题先澄清，针对实时状态直接说明能力范围。最终未检索的题为 008、022、027、029、030，均保留在原始记录。

## 残留问题与决策

`DIAN-RAG-004` 的最终回复把“已签收”解释为“已收到商品”。这与签收争议规则“签收记录不能证明实际收件”存在冲突。状态枚举本身正确，解释仍有误。这一例说明，工具调用成功或找到充分证据无法替代最终语义检查。

一些回复还带有语料未规定的页面入口建议或一般技术排查。用户需要据此办理真实业务时，应继续验证这些建议的适用性。当前九片段、已曝光开发题的观察不足以支持生产准确率。

保留本轮提示词改进及直接 BM25 业务基线。下一步先验证跨文档事实约束，围绕“状态记录与实际收件”加入少量独立表述检查，再将候选放入 HTTP /chat 的实际路由和角色组合中观察。真实只读接口接入需要供应商契约、授权账户与可用运单。当前没有因本轮结果增加重排服务或重试层。
