# DiAn A3 检索评测最小接入验收

本轮按[工程能力审查的 A3](DiAn-AgentInfra工程能力审查与优化方案.md)准备检索证据，建立公开数据适配、业务候选标注及配对评测。核心问题为查询改写与重排是否改善最终相关证据，代价为额外检索、模型调用和延迟。

## 数据与许可

选用 [MIRACL 官方问题与相关性标注](https://huggingface.co/datasets/miracl/miracl)。其中文训练数据包含人工标注的相关和不相关段落。[官方语料说明](https://huggingface.co/datasets/miracl/miracl-corpus)记录段落来自中文维基百科。数据卡标注 Apache-2.0，维基百科文本另需遵循其原始来源条款。上游发布数据及文本的权属分别保留。

下载固定的 Hugging Face Parquet 转换提交 `ad2acf33f265b8fba92e5096c9d2cf569a82b067`，文件 SHA-256 为 `56798d5cbc601a6f1fa8df72f37ef37c4f26911e0cbc42d5b26d04cc43731f1e`。以 `sha256("dian-a3-v1" + query_id)` 排序，取前 30 个问题，将其全部已标注正负段落合并为共享的 299 段候选库。原始数据、问题文本、转换文件及逐次日志保存在忽略提交的 `backend/data/rag-a3/`。公开仓库保留下载器、哈希、来源、问题 ID、段落 ID 和脱敏实验报告。

这种候选库便于验证链路与指标，也使用了上游标注确定候选范围。报告适用于此共享标注池，上游全库中文检索有约 493 万段。其他问题带入的段落对当前问题可能没有人工判定，按评测惯例以零增益计分，同时报告未判断比例。上游正例未再次切分，避免将原段落标签直接套用到新片段。

[业务标注草稿](../evaluation/datasets/dian_rag_v1/README.md)采用当前九篇演示知识和 30 个自建问题，保留对应原文、片段身份和版本。27 条有候选证据，3 条涉及语料缺失的事实。全部为待人工复核，复核者字段为空。脚本检查引用和哈希，人工继续核对条件、证据充分性与替代证据。

## 配对与指标

最终均返回三个段落。各轮按问题轮换组别执行顺序，缓存关闭，先预热本地向量模型。向量为现有 Chroma 默认的 all-MiniLM-L6-v2，记录模型文件哈希和实际 L2 索引距离。改写及重排复用现有 `MCPToolManager` 方法，模型输入仅包含问题、候选文本及检索元数据。

| 配置 | 实际召回及排序 |
| --- | --- |
| single | 原查询取 3 条 |
| rewrite | 原查询与最多 3 个改写各取 5 条，按现有顺序合并去重，返回前 3 条 |
| rerank | 原查询取 5 条，模型重排后取 3 条 |
| full | 最多四路各取 5 条，合并后模型重排取 3 条 |
| budget_single | 原查询取 20 条，截取前 3 条 |
| budget_rerank | 原查询取 20 条，模型重排后取 3 条 |

后两组对照最多 20 个召回名额，观察增加召回深度能否解释完整组的收益。实际唯一候选数及检索次数可能因改写重复而不同。当前生产合并顺序保留原查询优先，没有跨查询融合排序，纯改写组会保留这一行为。重排继续采用现有每项前 200 字符输入，片段被截断可能影响判断。

报告逐问题保存 Recall@1/3、nDCG@1/3、未判断比例、段落 ID、实际检索调用、模型调用与错误、供应商报告用量及端到端耗时。重复段落按身份去重，空结果的召回计零。没有正例的问题相关指标为空，当前公开运行仅接受带上游人工标注的有答案样本。改写和重排失败后的原路径回退保留，另记模型错误数量。

最小运行用于核对链路。正式候选实验需要预先固定保留门槛、完成至少五轮交错回放，并按问题配对分析质量、调用和耗时。业务回答的引用正确性及语义充分性继续需要独立验收。

## 复现

在 `backend` 目录安装项目及测试依赖，配置本地模型后执行。

```powershell
python -m pip install -r requirements-rag-eval.txt
python -m evaluation.prepare_rag_data --download
python -m pytest -q tests/test_rag_evaluation.py tests/test_tool_manager.py tests/test_knowledge_base.py
python -m evaluation.compare_rag --env-file .env --rounds 1 --limit 8 --output data/rag-a3/smoke.json
```

公开实验初步验证后，可使用新的输出路径运行 `--rounds 5 --limit 30`。显式 `--env-file` 只在评测进程内覆盖继承的变量，未指定时沿用环境变量优先的加载顺序。模型及向量检索配置由报告记录。修改业务草稿会改变快照，应保留版本与复核记录。准备器拒绝覆盖内容不同的已有语料或标注，修订时使用新的目录。

## 2026-11-18 最小运行结果

先以源码 `9679c91` 运行八个问题、六组配置、各一轮。环境变量继承的旧模型地址产生 40 次模型连接错误，48 个组别执行完成，所有增强组都走回退。结果保留在[公开报告](../evaluation/rag_ablation_smoke.json)的 `inherited_endpoint`。

随后在 `81cc070` 使用显式本地配置复跑相同问题和候选库。中间完善了显式配置、候选 ID 记录、跨系统换行哈希与快照覆盖保护。没有更换模型标识或向量文件。第一轮与复跑的文件哈希因规范化换行而不同，两份报告分别保留对应快照及源码身份。第二轮模型为 `deepseek-v4-pro`，40 次模型调用中 30 次成功、10 次连接失败，各组回退样本仍保留在指标分母中。

全部指标按八个问题求均值。基线前 3 段的未判断比例为 0.5000，完整组和深召回重排组为 0.2083，进一步限制了相关性结论的强度。30 次成功调用报告输入 23775、输出 1002 token，失败调用用量未知，实际费用未估算。

本轮有三个观察。纯改写增加了检索次数，但原查询先占据最终前三，当前顺序合并方式无法让补充候选进入结果。完整组在这八题的 nDCG 较高，单查询深召回加重排的 Recall@3 更高，成本也不同。当前基础向量的前排正例覆盖较低，后续需要检查候选召回与重排截断分别造成的损失。

这些观察来自共享候选池、单轮小样本和不一致的实时连接故障。本轮完成数据与评测最小接入，生产配置决策继续等待正式配对实验与业务人工复核。当前仓库的业务草稿没有人工签名，也没有被计入公开检索成绩。

专项测试 `tests/test_rag_evaluation.py`、`tests/test_tool_manager.py`、`tests/test_knowledge_base.py` 本机共 15 项通过。新增测试验证分级相关性、重复与未判断片段、快照篡改、证据引用、覆盖保护、确定抽样和模型输入隔离。
