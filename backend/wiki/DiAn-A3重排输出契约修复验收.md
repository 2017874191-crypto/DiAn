# DiAn A3 重排输出契约修复验收

本轮处理连接修复后仍存在的重排回退，按“先复现、只改一个机制、固定输入对照”的顺序验证。结论是：新提示词在当前八题三轮实验中提高了完整索引输出的通过率；两组检索指标相同，尚未观察到本次提示词调整带来的相关性收益。

## 原因与证据范围

[上轮连接验收](DiAn-A3模型连接故障修复验收.md)的 `rerank` 组有七次模型请求成功、重排接受失败。那次没有保存回复正文，因此这七次的具体内容仍无法逐条还原。

在原代码 `cc107f2` 上独立复现原提示词，共 24 次调用，无模型错误，其中四次返回空数组，两次为 `[]`、两次为带代码块的空数组。另外三次仅返回 `[4]`，旧解析器补齐了遗漏索引后计为通过。[独立复现记录](../evaluation/rag_rerank_contract_diagnosis.json)保留公开样本的回复、候选 ID、提示词哈希与调用记录。

旧提示词同时要求“相关性打分（0-10）”和“返回索引顺序”，也没有明确要求保留全部候选。观测到的空数组和单索引与完整排序契约不符。提示词歧义是本轮修复假设；具体模型内部如何作出这些输出无法由接口直接证明。

## 实现与取舍

- 在 `MCPToolManager` 内集中定义重排提示词与索引解析。提示词只要求相关性排序，要求每个候选索引恰好出现一次；所有候选不相关时仍返回相对顺序。
- 保留原有严格索引类型与范围检查。空数组、无文本、非法 JSON、非法索引、截断均回退到检索原顺序。不会把空数组补齐后算作成功。
- 保留已有的部分索引补齐与重复索引去重兼容行为，新增独立计数。`rag_rerank_accepted` 可以包含修复结果；判断完整有效输出必须同时确认没有 `rag_rerank_repaired`。
- 记录固定枚举原因：`no_text`、`invalid_json`、`empty_order`、`invalid_index`、`truncated`、`model_error`，另记小候选池跳过。常规调用仅记录计数，不记录回复正文。
- 原六组评测分别输出 `transport_events` 与 `rerank_events`，便于区分连接成功、输出接受和兼容补齐。

本轮采用提示词澄清和本地校验，避免增加专用重排服务、额外模型调用或自动重试。代价是 JSON 输出仍受模型行为影响，后续模型与数据变化需要继续检验。排序器强制保留候选意味着调用方仍须独立判断证据充分性；完整索引列表不代表问题可回答。

## 只改变提示词的配对实验

新增 `evaluation.compare_rerank_contract`，使用上游已人工标注的公开 MIRACL 开发子集。旧模板逐字保留自 `cc107f2`，新模板调用生产方法。两组经过同一解析器、同一模型方法。

固定八个问题、299 个段落、原向量文件、L2 距离、每题五个候选、最终三个结果。每题候选只计算一次，两组候选完整内容的 SHA-256 相同。温度为 0，输出上限 2048 token；每组最多一次调用，SDK 重试为 0，共享直连客户端。三轮交错执行旧、新组，排除改写和工具缓存。

实验代码为 `b436ec8`。[逐条公开报告](../evaluation/rag_rerank_contract.json)保存回复正文、候选哈希、提示词哈希、实际调用、事件和指标。正文仅针对这批公开语料记录；常规评测和线上日志沿用计数。

| 指标 | 旧提示词 | 新提示词 |
| --- | ---: | ---: |
| 执行 / 模型调用 | 24 / 24 | 24 / 24 |
| 模型调用错误 | 0 | 0 |
| 完整有效输出，无需补齐或去重 | 16 / 24 | 24 / 24 |
| 接受输出，包含兼容补齐 | 19 / 24 | 24 / 24 |
| 兼容补齐 | 3 | 0 |
| 空数组回退 | 5 | 0 |
| Recall@3 | 0.15625 | 0.15625 |
| nDCG@3 | 0.144295 | 0.144295 |

本次配对证明了当前样本中的输出契约改善，相关性指标没有增加。空数组回退保留的结果可能与有效排序得到相同前三，因此格式改善不必然改变检索指标。八题重复三次仍只有八个独立问题。

独立复现与配对实验的旧模板相同、候选 ID 相同，有一题的完整提示词哈希在两次运行间不同。独立复现未保存完整候选对象，无法还原该差异；严格的候选输入一致断言限于配对实验内部。报告保留此限制，独立复现的四次回退与配对实验的五次回退分别统计。

## 集成验收

代码 `2ce7d58` 再运行原六组评测，八题一轮共 48 次组别执行、40 次模型调用，无模型错误。`rerank`、`full`、`budget_rerank` 各八次，共 24 次重排均通过，没有回退或兼容补齐，覆盖五候选、改写合并候选与二十候选路径。[集成报告](../evaluation/rag_rerank_integration.json)保留全部组别与指标。

专项 50 项测试通过，覆盖空数组、无文本、非法 JSON、布尔/浮点/字符串/越界索引、截断、模型异常、小候选池跳过、兼容补齐、单次调用预算、模型输入不含金标和工具状态隔离。GitHub [代码提交自动检查](https://github.com/2017874191-crypto/DiAn/actions/runs/44462959056)通过，包含后端测试、真实 Redis 陈旧写回归及前端测试与构建。

模型配置、公开语料准备和依赖见[最小接入验收](DiAn-A3检索评测最小接入验收.md)。真实模型回复可能波动，报告记录的是当次观测。

## 能力边界与下一步

当前验收范围是重排输出契约及六组链路兼容。每项候选仍按序列化后的前 200 字符提供，相关证据可能被截断；基础向量前排的正例覆盖也有待改善。公开子集使用共享标注候选池，其他问题带入的未判断段落按零增益计分，不能推导生产准确率。

下一步先在同一冻结数据上分开核对“正例未进候选”和“正例已进候选但排序丢失”，检查 200 字符展示是否遮蔽证据；据此只选择一个变量设计下轮对照。正式配置决策继续按原文档预先固定门槛并完成至少五轮实验，同时推进 30 条业务标注草稿的人工复核。业务人工签名、引用正确性和语义充分性仍需真实复核者验收。
