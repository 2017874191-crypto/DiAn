# DiAn 故障追踪与物流向量开关验收记录

日期：2026-11-10。范围仍是固定模拟工具世界的 30 案开发集；冻结测试集未进行模型评分，也未接入真实业务系统。

## 1. 故障复核与修复

上轮 `DIAN-029` 首次返回 `agent_failed`，旧回放器丢弃了 HTTP 503 的调用诊断，因此无法追溯到具体异常。保留旧报告不改写；随后在独立会话中连续探测 8 次，8/8 通过，尚不能确定首次失败原因。现在回放器对 503 保存请求号、意图、Agent、阶段耗时、模型调用阶段与状态、异常类型及失败后的工单数量；调用记录不含提示词或密钥。Agent 异常日志也增加请求号和异常类型，供下一次故障关联。

在开关初次对照中另发现 `DIAN-023` 流程失败：用户只问“寄送一件商品的运费怎么算？”，意图模型调用 15 秒超时，本地向量把请求分类为 `logistics_damaged`，错误创建了 `awaiting_info` 案件，工单数仍为 0。独立重算该句：规则分类为 `query`、置信度 0.75；本地向量分类为 `logistics_damaged`、置信度约 0.205。按当时 `_vote` 的模型失败分支，向量结果会直接覆盖规则结果，这是根据报告、代码路径与独立重算得出的故障原因。

修复后，模型失败时若向量给出细粒度物流异常、而规则没有明确识别该异常，则不能仅凭向量启动案件；保留规则分类或安全澄清。明确“包裹破损”等规则命中仍可继续核验。物流领域状态机、确认门槛及写操作代码不受此开关影响。

## 2. 单独关闭物流向量分支

新增 `INTENT_LOGISTICS_EMBEDDING_ENABLED`，默认 `true`。在 `INTENT_RECOGNITION_MODE=full` 且开关为 `false` 时，先取得模型与规则的意图：任一分支识别为物流候选，就对该请求使用 LLM＋规则投票；其他领域继续使用向量分支。非物流请求可能因先等待模型再调用向量而增加时延，这是该隔离开关的实现代价，须以实测验证。`rules_only`、`llm_rules` 两种模式的原有含义保持一致。

两组使用同一镜像 `sha256:b50ba8d93caf9076501dfd6dab4c5e164654b6b8e1c4c542007ce73a2c74ff21`、同一开发集与模型配置，各自独立的 Redis、Chroma 卷、案件数据库；按顺序运行并在完成后停止容器。

| 指标 | 完整方案，物流向量开启 | 完整方案，物流向量关闭 |
| --- | ---: | ---: |
| 流程断言通过 / 30 案 | 30 | 30 |
| 意外模拟工单 | 0 | 0 |
| 已观察轮次 | 45 | 45 |
| HTTP 往返 P50 / P95 | 1625 / 5562 ms | 1500 / 5015 ms |
| 记录到的模型调用 / 错误 | 56 / 0 | 50 / 0 |
| 服务方报告的输入 / 输出 token | 8158 / 3527 | 6029 / 3108 |

两组流程均通过，未观察到关闭物流向量造成回归。耗时、调用与 token 差异来自各一次完整回放，模型路由和回复具有波动；向量分支本身不调用该对话模型，不能把模型调用数差额解释成向量调用节省。回复语义仍待人工复核，以上分数不是生产准确率。原始报告分别位于 `data/ablation-logistics-switch/v2-control/eval/report.json` 和 `data/ablation-logistics-switch/v2-logistics-off/eval/report.json`；修复前 `DIAN-023` 证据位于 `data/ablation-logistics-switch/control/eval/report.json`。

## 3. 冻结测试集人工复核准备

已生成两份互不包含对方填写栏的空白复核表：`data/acceptance/eval/test-reviewer-1-blank.csv`、`data/acceptance/eval/test-reviewer-2-blank.csv`，均覆盖 20 案、28 轮。新校验器逐行检查冻结数据集身份、期望字段、复核者身份、结论枚举与修订理由，并统计一致与分歧；它不改写金标。当前校验为两人各 0/28、`ready_for_adjudication=false`、`gold_frozen=false`。没有代替人工作出语义判定。

## 4. 本轮验收与后续门槛

- 最终本地 P0 验收为 38 项通过；意图、模型调用统计、对话可靠性等补充测试为 54 项通过。隔离 HTTP 开关对照另行完成，两组各 30/30。数据集结构校验通过，共 50 案、73 轮。上游源记录本轮未复核，`source_record_check=false`。
- `DIAN-023` 的误建案路径已有回归测试；失败请求的安全诊断字段、物流开关对其他领域的保留行为、独立复核表与校验器均有针对性测试。
- 保留默认 `INTENT_LOGISTICS_EMBEDDING_ENABLED=true`，把关闭配置作为物流路径候选方案。至少再做跨时段重复回放、失败注入和人工语义复核，确认稳定性与非物流延迟后再决定是否调整默认值。
- `DIAN-029` 的原始异常仍未定位。下一次出现时按请求号关联 HTTP 回放、模型调用阶段与异常类型，不以单案复测通过抹去首次失败。
- 两位真实复核者完成测试集金标复核、分歧裁决和版本冻结之前，不报告冻结测试集模型分数；之后才推进真实 provider 的超时、鉴权、结果未知与幂等契约。

复核表操作与校验命令见 `wiki/DiAn测试集人工复核说明.md`。重复回放可沿用 `wiki/DiAn-P2规则与消融验收记录.md` 的隔离 Compose 命令，并分别设置 `DIAN_LOGISTICS_EMBEDDING_ENABLED=true/false`、独立项目名与数据目录。
