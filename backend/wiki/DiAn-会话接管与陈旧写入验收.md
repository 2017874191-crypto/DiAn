# DiAn 会话接管与陈旧写入验收

实验日期为 2026-11-17，基线为 `5152792`。Redis 租约的续租失效可以取消协程，但取消可能比旧写入更晚，且已经发给线程池的 SQLite 操作可以继续。Redis 和 SQLite 分别在各自的提交点作校验。

## 写入与接收语义

| 范围 | 提交条件和可查询状态 |
| --- | --- |
| Redis 会话回执 | `/chat` 把会话租约传给回执写入。对租约键执行 `WATCH` 后确认仍持有原 token，再用同一个 Redis 事务提交会话状态、聊天记录、回执和轨迹。检查后若租约过期、被替换或续租，`EXEC` 会中止，最多重试三次。失去租约返回 503。 |
| SQLite 物流命令 | 读取会话的业务版本后核验 Redis 租约。案件、当前案件关联和 Run 写入在同一 SQLite 写事务内校验并递增该版本。前台人工核查状态写入也校验版本。新请求先推进后，携带旧版本的写入返回 409。 |
| 独立 HTTP 工单 | 案件与待核对 Operation 提交后才派发模拟外部操作。晚到的前台结果只能提交到对应版本。已有远端工单仍可由后台按稳定键 GET 核对，后台会更新原案件和相关 Run。当前案件关联由前台命令管理。管理员已挂起时仍能保留已观察到的工单号。 |
| 请求的持久接收 | 进入 HTTP 处理、获得会话租约和进入排队都属于临时状态。默认物流在案件和 Run 事务提交后有业务记录。可以查询 `GET /logistics/case` 查看当前案件，有 Run ID 时可查 `GET /logistics/runs/{run_id}`。相同请求 ID 的 Redis 回执表示那一轮的原结果。 |
| 可选 Temporal | 原有接收事务保存待派发记录和 Run，Worker 按原工作流继续执行。新版本校验针对默认前台路径，Redis 回执检查也适用于可选路径的 API 响应。 |

## 独立进程对照

运行真实 Redis 7.4.12 和两个独立进程，ASGI 请求进入同一 `/chat` 路由，使用同一个临时 SQLite 库。旧进程处理订单 DEMO1001 时使用操作系统暂停整个进程。控制器将该实验租约的剩余 TTL 缩短至 300 毫秒，等待 Redis 自行过期。新进程再推进 DEMO1002，提交成功后才恢复旧进程。模型和路由固定，测试分别卡在 SQLite 写入和 Redis 回执写入前。

| 暂停位置 | 旧实现 | 新实现 |
| --- | --- | --- |
| SQLite 业务写入前 | 旧执行返回 200，SQLite 和 Redis 当前案件都被改回 DEMO1001 | 旧执行返回 409，SQLite 与 Redis 都保留 DEMO1002，旧回执未写入 |
| Redis 回执写入前 | 旧执行返回 200，SQLite 保留 DEMO1002，Redis 被旧会话状态覆盖 | 旧执行返回 503，SQLite 与 Redis 都保留 DEMO1002，旧回执未写入 |

另一个 Redis 回归在持有者检查后立即换掉租约 token，证明结果提交仍会被 `WATCH` 拦截。独立 HTTP 模拟服务的集成测试让原工单先提交，再等待新请求推进另一案件。迟到的旧回调被拒绝后，后台 GET 取回原工单。新案件关联保留，远端工单数为 **1**。

暂停工具的首次试跑卡在 Windows 同步事件上，等待超过 HTTP 时限，属于测试夹具故障。调整为先恢复进程再发送继续信号后，才采集表中的两组结果。[对照结果](../evaluation/stale_chat_write_comparison.json)

## 复现

在 `backend` 目录使用项目测试依赖、可运行的 Docker 和本机已有的 `redis:7-alpine` 镜像。脚本每次创建独立容器与临时库，结束后停止该容器。在基线代码中放入同一实验脚本后以 `--expect baseline` 复现对照组。

```powershell
python -m evaluation.compare_stale_chat_write
python -m pytest -q tests
```

本机 Windows / Python 3.11.9 后端全量 **249 项通过**，有一条既有测试依赖弃用警告。真实 Redis 断线重连、跨进程锁互斥及 Redis 与 HTTP 模拟工单联合故障也完成了回归。联合故障中，默认路径和可选 Temporal 路径都在新一轮查询中恢复为已建单，远端各保留一张工单。

## 能力边界

SQLite 版本保护发生在新业务版本提交之后。Redis 租约过期与 SQLite 提交属于两个存储系统，已经取得 SQLite 写事务的旧执行有可能先提交。外部 POST 与本地提交也属于独立事务，迟到的远端结果依靠 Operation、稳定键与权威 GET 收敛。验收限于本机进程、单 Redis、共享 SQLite 和模拟 Provider。多机部署、真实工单接口的幂等契约及通用异步接管仍需分别验证。
