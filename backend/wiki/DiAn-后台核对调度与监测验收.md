# DiAn 后台核对调度与监测验收

日期为 2026-11-17，基线为 `abc0440`。旧核对器按 Operation 更新时间取前 100 条。查无结果和查询异常都不改变这两项排序条件，足够多的旧未决记录会占满后续批次。

## 改动与边界

- 核对器在现有 SQLite 库记录每个 Operation 的核对次数、最近核对时间、下次到期时间和结果类别。首次核对沿用至少 10 秒的业务记录年龄门槛。每轮取最多 100 条符合条件的记录，按到期时间和稳定操作键排序。查无结果、查询不可用和冲突按 10、20、40、80、160、300 秒退避，此后间隔上限为 300 秒。旧记录首次参与调度时沿用原业务更新时间。
- 调度元数据与业务记录分表保存。退避不会重置未决年龄，也不会替未决操作判定失败或解除业务占用。管理员可从 `GET /logistics/operations/pending` 查看核对记录并沿用现有挂起入口。挂起操作退出自动扫描。
- 核对器只调用现有 HTTP 模拟 Provider 的 GET。成功结果继续由领域服务检查案件归属、确认版本、参数和挂起状态。并行核对可能重复 GET。当前部署按单核对器配置运行，现有并发回归覆盖共享 SQLite 的结果提交与挂起竞态。
- HTTP 模拟模式的 `/metrics` 暴露 `dian_ticket_reconcile_last_completed_timestamp_seconds`。零表示该库尚未完成一轮扫描。空批次也会刷新该值。远端不可用但扫描完成时，指标只说明核对器仍在运行，待处理记录和积压告警仍需查看。若扫描中途因持久化失败退出，指标保留上一轮时间。
- `DiAnTicketReconcilerStalled` 在指标为零或距上次完成超过 600 秒，并持续两分钟后触发。它要求 API 指标可抓取且 API 与核对器共享案件库。自定义扫描周期时需要使告警阈值与扫描周期和批量耗时匹配。告警通知投递和多机调度留待独立验收。
