# DiAn 固定模型故障对照验收

承接 [A1 意图消融复验](DiAn-A1意图消融复验.md)。上次含模型配置先后接入真实模型服务，发生的连接错误各不相同。本轮改用可重复的 SDK 传输故障，在同一案例、轮次和模型调用阶段施加同一个连接错误。验证范围为 `DIAN-019`、`020`、`023`、`024`、`025`，`DIAN-026` 单用于评测结案故障。

## 设计与实测

使用实际 `/chat` 路由、意图计算、Agent 执行、SQLite 和案件回放断言。Redis 由协议替身提供。健康组的模型意图与回复由固定替身返回。在故障组，Anthropic 客户端的本地 HTTP transport 在要求的位置抛出 `ConnectError`。通过测试数据和运行身份摘要确认配置以外的条件一致。每个组合使用独立 SQLite 与 Redis 替身。故障固定在第一轮，后续轮次的模型替身恢复。全部组合只运行本地试验。

| 故障条件 | 完整三路 | LLM＋规则 | 完整模式，关闭物流向量 |
| --- | ---: | ---: | ---: |
| 健康替身 | 5/5 | 5/5 | 5/5 |
| 首轮意图模型断连 | 4/5 | 4/5 | 4/5 |
| 首轮意图和回答模型都断连 | 0/5 | 1/5 | 0/5 |

三组在只断意图模型时都遗漏 `DIAN-025` 的含蓄丢件请求。向量开、关两组都走 `local-ngram` 回退为 `order_status`。当前开关依赖模型或规则先识别为物流候选。此样本在意图模型断连后没有这个候选信号，关闭组仍执行本地向量。这解释了两组在这条输入上的同一结果。

两个模型阶段均断连时，仅 LLM＋规则对 `DIAN-019` 走了无模型的固定澄清，满足了该案目前的流程断言。这一案仍需语义复核，流程通过只表示符合已有状态、角色和副作用预期。四个正常查件或运费咨询用例在所有组合均未建立异常案件或工单。断连的 `DIAN-025` 未建立工单，健康对照只在下一轮明确确认后建单。该实验的用途是隔离回退路径和副作用，保留现有默认意图模式和物流向量开关。

## 评测结案连接故障

在实际管理员结案入口分别注入提交前断连、提交后响应丢失和持续断连。原接口按案件、主体和会话核验；重复提交已结案请求时返回同一 `closed_at`。回放器沿用该接口，只在传输异常时用同一请求再试一次，每次最多等待 5 秒。结果记录尝试次数和错误类型。明确 HTTP 拒绝直接记录一次失败。

| 注入点 | 仅尝试一次 | 新回放器 |
| --- | --- | --- |
| 提交前断连 | 环境失败，案件仍打开 | 第二次完成结案，保留首次错误 |
| 提交后丢响应 | 环境失败，实际已结案 | 第二次取回原结案时间，保留首次错误 |
| 持续断连 | 环境失败，案件仍打开 | 两次后保留环境失败与两次错误 |

以上各组只保留一张模拟工单。重试范围限于评测清理。上次真实模型消融的失败记录继续按当时流程保留。

在 `backend` 目录安装测试依赖后复现：

```powershell
python -m evaluation.compare_intent_faults --output data/intent-faults.json
python -m pytest -q tests/test_intent_fault_ablation.py
```

本轮验证了已选案例对固定故障的行为。供应商真实故障、更多含蓄物流表述、回答语义及生产性能需要独立证据。已掌握的共同缺口是意图模型断连后对 `DIAN-025` 的澄清或业务接续。

本机后端全量 264 项通过。公开产物记录 45 个意图故障组合和六个独立结案故障组合，含模型调用阶段、HTTP 状态、SQLite 行数和原始配置身份摘要。[固定故障结果](../evaluation/intent_fault_ablation.json)

定向澄清的实现、反例与消融见[断连未收货澄清验收](DiAn-断连未收货澄清验收.md)。
