# DiAn 有界执行与模型预算验收

基线为 `2fdcc98`。旧版虽有会话锁与聊天超时，但默认物流调用在事件循环上同步等待 SQLite。会话锁只能约束同一会话，无法限制不同会话的并发。改动沿用现有会话锁、业务状态机和模型调用封装，在一套 API 进程内限制资源消耗。

## 运行契约

| 范围 | 默认值与行为 |
| --- | --- |
| `/chat` | 16 个执行槽、32 个等待位。启用鉴权时，每个账户最多占 4 个槽或等待位，额度基于 Token 映射身份。 |
| 模拟物流执行 | 同一进程内的默认 SQLite 和独立 HTTP 模拟路径共用 4 个执行槽、8 个等待位。候选操作取得执行槽后才写确认回执和提交工作。人工核查状态写入走同一额度。 |
| Anthropic 兼容模型 | 在线 8 个执行槽和 16 个等待位。评测为 2 和 4，画像维护为 1 和 4。每轮聊天最多 16 次已发起的调用，失败也计入，应用创建的 SDK 客户端关闭内置重试。 |
| 等待与超时 | 单次容量等待上限为 2 秒。`/chat` 进入处理函数后总时限为 50 秒，覆盖排队、会话锁等待和执行。入口或物流容量拒绝返回 429 与 `Retry-After: 2`，聊天总时限触发返回 504。模型容量在调用层执行，意图、检索和 Agent 可按原有策略降级。 |

配置见 [`.env.example`](../.env.example)。模型传输层单次默认最长 30 秒，仍受意图、Agent、合成阶段的各自超时与聊天总时限约束。`/metrics` 公开 `dian_capacity_active`、`dian_capacity_waiting`、`dian_capacity_rejected_total`，以有限的资源类别作为标签。调用预算用尽与模型容量拒绝可在聊天性能记录的事件计数中区分。

当 HTTP 等待超时或处理任务被取消，已提交给线程池的同步物流操作继续占用执行槽。API 执行任务等线程退出再释放会话锁与聊天额度。已经进入本地确认写入的请求可能随后完成，客户端应查询案件状态，并沿用原 `client_request_id` 获得已有回执。可选 Temporal 路径沿用原有持久接收及 Workflow 结果语义。

## 对照与反例

SQLite 对照在同一个 FastAPI 入口、临时案件数据库和相同的写锁注入下进行。旧版 `/health` 返回 200 时物流已结束。新版 `/health` 返回 200 时物流仍在等写锁，释放写锁后原请求正常完成。这个反例覆盖事件循环能否在 SQLite 等待期间服务其他请求。

接入消融固定 6 条并发请求、独立会话、受控识别等待和同一个认证账户分布。A 发出 4 条，B 和 C 各发 1 条。下表在释放等待条件前采样。宽松额度在这组负载下不会触发限额。

| 接入配置 | 执行中 | 等待中 | 拒绝 |
| --- | ---: | ---: | ---: |
| 宽松执行上限 8 | 6 | 0 | 0 |
| 进程执行上限 2，等待位 4 | 2 | 4 | 0 |
| 进程执行上限 2，等待位 4，账户上限 1 | 2 | 1 | 3 |

额外验证：

- 分别让排队时限和聊天总时限先到，验证 429、504 与未启动请求没有回执。恢复额度后新请求可以正常处理。
- 暂停已开始的 SQLite 确认，先收到 504。此时会话锁与两个执行额度仍被占用，另一会话的确认因容量耗尽收到 429，且未写入确认回执。释放执行后，原案件成功创建一张模拟工单，原请求 ID 重试读取已有的未知结果回执。
- 使用真实 SDK 与受控 HTTP transport 连续返回 429，预算 2 时观察到两次实际 HTTP 请求。第三次调用在本地被预算拒绝。模型失败的 token 用量保留为未知。在线模型处于饱和时，评测仍能使用自己的额度，在线调用取消后可再次获得原额度。

在 `backend` 下复现：

```powershell
python -m pytest -q -s tests/test_chat_reliability.py tests/test_llm_utils.py tests/test_concurrency.py
python -m pytest -q tests
```

## 适用范围

额度作用于单个 API 进程。未开启鉴权的演示模式只使用进程额度。后台核对器是独立进程，后台模型通道仍共享上游供应商额度。模型调用预算针对 Anthropic 兼容生成调用，嵌入、MCP 和其他外部服务的独立预算留待专项验证。

对照使用本机共享 SQLite、模拟工单服务、Redis 协议替身和受控模型。生产延迟、吞吐与多实例配额需要独立压测。真实 Redis 过期与进程暂停的后续验证见[会话接管与陈旧写入验收](DiAn-会话接管与陈旧写入验收.md)。
