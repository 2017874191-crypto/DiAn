# DiAn 简历项目模板

DiAn 基于 EchoMind 的通用客服框架扩展物流异常处理。框架来源见 [NOTICE](../../NOTICE.md)，物流领域改动和实验证据见 [项目说明](../../README.md)。

## 简历项目经历

- 基于 EchoMind 扩展物流异常协同台，覆盖疑似丢件、签收争议和破损错发，按核验、举证、用户确认推进案件并创建模拟工单。
- 实现持久案件关联、Run/Step 和 Operation，核对远端模拟工单的未知结果，并按用户、已核验订单和问题类型限制跨会话重复建单。
- 建立 50 案、73 轮的物流回放集，检查状态、轨迹、工单数与前置条件。对可选 Temporal 物流路径与默认路径进行故障对照，比较恢复行为与开销。
- 对照规则、LLM＋规则和完整配置。首次 30 案开发集回放中，LLM＋规则通过 30 案，完整配置通过 29 案，完整组有一次服务失败。将 LLM＋规则作为物流演示和后续实验的基线。[模式对照报告](DiAn-P2规则与消融验收记录.md)

## 当前实现

| 项目 | 可核对的范围 |
| --- | --- |
| 意图识别 | 22 个枚举值，含兜底 `other`。完整模式按固定权重合并 LLM 自报置信度、模板相似度和关键词规则分，融合分未经统一校准。 |
| Agent | General、Technical、Billing、Logistics、Escalation，共 5 种。 |
| Skills | 通用客服、技术支持、账单支持、物流支持，共 4 个模块。 |
| 知识库 | 意图识别提供路由信息。获得 `search_knowledge_base` 工具的 Agent 由模型按需调用，物流案件由领域代码推进。 |
| 检索 | 一次未命中完整流程缓存的检索保留原查询，最多加入 3 个改写查询，去重后最多并行发起 4 路 ChromaDB 向量召回，合并结果后按需重排。改写失败时使用原查询。 |
| 评测 | 内置 11 条意图用例和 5 组编排层对话用例。物流案件回放集为 50 案、73 个用户轮次，其中开发集 30 案、测试集 20 案。 |

## 评测口径与证据

- 意图分类指标来自模型预测与标注对比。引用分数时注明用例数、配置和具体报告。[默认用例](../evaluation/evaluator.py#L703)
- 物流案件回放检查案件状态、工具轨迹和工单数量等确定性条件。开发集的流程通过数按实验配置和样本范围引用，回复语义需要独立复核。[数据集清单](../evaluation/datasets/dian_logistics_v1/manifest.json) · [开发集对照记录](DiAn-P3故障追踪与物流向量开关验收记录.md)
- RAG 召回率需指定标注相关片段、检索配置和 Top-K。当前项目经历引用检索机制和可核查的用例规模。
