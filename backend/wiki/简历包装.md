# DiAn 简历包装指南

本文档用于把 DiAn 项目包装成简历、面试和项目展示中可讲清楚的经历。建议按真实实现描述，量化数据如果没有压测或标注集支撑，应写成“设计目标”或“在内置评测集上”。

包装重点：DiAn 当前不建议只包装成“智能客服 Agent”，更适合定位为“多 Agent 客服编排/ Multi-Agent Customer Support”。项目已经支持细粒度意图识别、结构化路由决策、主辅 Agent 协同、RAG 知识增强、动态 Skills、异步记忆访问、Monitor 路由降权和 LLM-as-Judge 评测闭环。这是区分“普通聊天 Demo”和“可观测、可评测、可持续迭代 Agent 工程项目”的关键点。

## 项目一句话描述

> DiAn 是一个面向复杂客服任务的多 Agent 编排运行时，集成细粒度意图识别、结构化主辅 Agent 路由、动态 Skills 规则注入、Redis + ChromaDB 记忆体系、Agent 按需调用的 RAG 知识增强、MCP 工具可靠性治理、Monitor 在线降权闭环和 LLM-as-Judge 编排层对话评测。

### Agent 编排层怎么评测？

**回答思路**

评测分两部分：

1. 意图识别评测：用标注用例计算 Accuracy 和 Macro-F1。
2. 编排层回复评测：真实调用 `Orchestrator.run()` 生成回复，再用 LLM-as-Judge 从四个维度打分。

四个维度是：

- `relevance`：是否回答用户问题。
- `accuracy`：信息是否准确。
- `completeness`：是否完整解决需求。
- `helpfulness`：用户能否据此行动。

评测器还会和上一轮结果对比，如果某个指标退化超过 5%，会标记为 regression，并生成优化建议。
